📚 CQRS in .NET Core (4 min read)
CQRS, which stands for Command Query Responsibility Segregation, is a way of separating read and write operations in software architecture. It's like having a split personality, with one side handling data retrieval and the other side changing the system's state. It's like being both a librarian and a superhero at the same time!On the read side, you use queries to fetch data without making any changes. It's the safe and responsible side. Just like a librarian quietly fetching books for you.On the write side, you use commands to manipulate data and make things happen. It's the wild and adventurous side. Just like a superhero saving the day!In the example provided, they use Dapper or a data repository to execute queries and fetch data. It's like having a henchman to do all the searching for you.For commands, they use MediatR, which acts as a mediator between the client and the command handlers. It's like having a trusty sidekick who knows exactly where to go and who to talk to.So, implementing CQRS is like having a dual personality: a calm librarian on one side and an action-packed superhero on the other. It's like having the best of both worlds, without needing a phone booth to change outfits!
